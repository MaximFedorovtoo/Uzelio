# Uzelio desktop packages

Build and test locally. Users receive a native launcher and bundled Java runtime; Java and Docker are not user requirements.

Windows: `powershell -File tools/package-desktop.ps1 -Type exe`. The default version is `0.8.0`; the installer is `Uzelio-0.8.0.exe`. Use `-Type app-image` for an unpacked `Uzelio/Uzelio.exe` smoke-test launcher. Requires the repository's portable Temurin JDK 21.0.12.1+1 in `.tools/jdk-21.0.12.1+1`, Gradle 8.13 and portable WiX 3.14.1 in `.tools/wix-3.14.1` (or pass `-WixDirectory`). Prepare the toolchain with `powershell -File tools/bootstrap.ps1 -AcceptSdkLicenses`; bootstrap installs Android SDK platforms 35 and 36 and build-tools 35.0.0. Product Android builds use compileSdk 36; platform 35 remains available to the other local modules. The scripts configure their process environment and leave the system Java installation unchanged.

The pinned Windows x64 JDK ZIP comes from the [official Temurin release](https://github.com/adoptium/temurin21-binaries/releases/tag/jdk-21.0.12.1%2B1), SHA256 `f9d6e191ab098c0d416e7d588a24420a8621cd2f4720dab2459b8b7b2d2d8b4e`. Product sources target Java 17, while libsignal 0.105.4 requires a Java 21 runtime. `jpackage` runs from this JDK and creates the bundled Java 21 runtime, including the `java.sql` module required by encrypted JDBC storage; app-image packaging verifies the runtime release file.

Obtain `wix314-binaries.zip` from the [official WiX release](https://github.com/wixtoolset/wix3/releases/tag/wix3141rtm). The official archive downloaded over HTTPS on 2026-10-22 has SHA256 `6AC824E1642D6F7277D0ED7EA09411A508F6116BA6FAE0AA5F2C7DAA2FF43D31`; the publisher does not provide a release digest and its portable candle/light executables are unsigned. The build script pins both executable hashes. The installer uses per-user scope, a stable upgrade UUID and Start Menu/desktop shortcuts. The desktop installer adds no firewall rule or autostart; the optional elevated routing setup adds program-specific inbound firewall exceptions for its helper.

macOS and Linux packaging is outside the validated Windows messenger toolchain. The existing `tools/package-desktop.sh` recipes require separate Java 21/runtime-module integration and host validation before packaging the messenger on either platform. macOS signing/notarization needs the owner's credentials and separate release authorization.

Messenger dependencies are free components with redistribution obligations: libsignal 0.105.4 (AGPLv3), Windows `io.github.willena:sqlite-jdbc:3.53.4.0` (Apache-2.0 JDBC with MIT SQLite3MultipleCiphers), and Android SQLCipher Community 4.19.1 (Zetetic BSD-style terms). Windows uses the independent SQLite3MultipleCiphers implementation with its SQLCipher cipher profile; it is not Zetetic's commercial JDBC product. Preserve license/notices and provide the corresponding source as required by libsignal's license when distributing. `THIRD_PARTY_NOTICES.txt` accompanies desktop package input; the bundled runtime retains its OpenJDK legal directory. This integration does not change the project's own license or certify release compliance.

Output is under `dist/desktop/`. Packages are unsigned unless separately signed by the owner. Do not imply publisher trust or macOS notarization.

State is independent of install location: Windows `%LOCALAPPDATA%/PeerNet`, macOS `~/Library/Application Support/PeerNet`, Linux `$XDG_DATA_HOME/peernet` or `~/.local/share/peernet`. These legacy directory names and the identity storage format deliberately remain compatible with PeerNet so the Uzelio rename preserves identity, contacts and settings. Remove this directory explicitly only if the user wishes to forget the identity. `-Duzelio.data=...` redirects state for isolated local tests; the old `-Dpeernet.data=...` remains accepted. A process lock prevents concurrent instances from overwriting state.

The protected Windows routing component keeps its compatibility path `%ProgramFiles%/PeerNet-Routing-2.6.4`, broker filename, manifest, IPC and firewall rule identifiers. Uzelio checks that the installed broker matches the bundled version and requests its safe update before routing with an older helper. The updater replaces only the reviewed broker and its manifest hash under the established access controls; it does not rename or reinstall the existing driver. Routing rules exclude both `Uzelio.exe` and legacy carriers such as `PeerNet.exe` to prevent routing loops.

Network status describes known contacts, not global completeness or verified incoming reachability. Sharing and connection are explicit actions; running the directory does not start traffic forwarding. Windows application routing requires its separate component and UAC. Name rules apply to matching executable basenames across Windows users. Shared DNS, fragmented IPv6 and helper crashes can leave traffic direct; this is not a VPN kill switch. The advertised address is configured by its owner; the desktop does not automatically configure NAT traversal.
